# 0.07 架构与验证边界

## 沿用的骨架

`OpenDamageState → OpenTower/OpenSurface → OpenMacro → 紧凑静态废墟` 继续负责损伤数据、碰撞代理和生命周期。共享 `DestructionManager` 统一结算真实伤害结果、奖励、碎块预算与视听节拍。没有重新引入逐墙格节点或全城高级结构图。

## 新动作的职责

- `open/dual_pull.gd` 读取两个现有抓钩的目标、实际锚点与张力。只管理配对、约 0.7–1.4 秒蓄力、预览和提示；普通移动模型不变。玩家重置、暂停或目标失效会取消预览。
- `OpenTower` 的 kind 4 是牵引核。黑环提供识别，单个 MultiMesh 提供蓄力裂纹；预览不改损伤数据、不计分。断裂后标记隐藏，痕迹随残塔和宏块保存。
- `OpenZone.begin_dual_pull` 在改变任何弱连接前检查两座塔、锚点、站位、张力和两个宏块名额。随后同步发出两个 PULL 事件，断裂请求进入现有队列。已受损弱连接的断裂能量仍须通过建筑伤害门槛。
- `OpenMacro` 保留程序倾转，用 CharacterBody3D 平移扫掠查询实际接触；牵引产生的大块朝对方运动。宏块之间可互相阻挡、破坏接触墙格，随后重新合并碰撞外壳。
- 同一个双拉编号的大块发生首次有效碰撞时，额外加 700 基础分，再应用换点连击和连锁倍率。宏块对去重与深度上限限制重复传播；没有按计时器凭空发送互撞奖励。
- 宏块带原塔弱引用，命中不同代理不会伪造新的塔身份；连锁目标按逻辑建筑去重。抓钩射线使用玩家碰撞遮罩，不能穿过运动宏块抓后方墙面。
- 契约奖励只修改总分，由契约面板展示；命中反馈继续展示导致完成的撞击或互撞，不再被契约文字替换。

## 规模与限制

36 栋塔中四栋改为牵引核，组成两对，中心间隔 40 米；原三座连锁弱缝塔保留。没有扩大地图或同时模拟预算。

| 项目 | 本版边界 |
|---|---|
| 活动宏块 | 最多 3 个；双拉同时需要 2 个空位 |
| 真实小碎块 | 共用 48 个；每次从原预制体生成 3–6 个 |
| 视听特效根 | 最多 8 个；大量小碎屑为 GPU 粒子 |
| 连锁深度 | 最多 2；一次宏块对有效碰撞只奖励一次 |
| 持久状态 | 本局墙格、切口、主要伤痕和废墟；无跨启动存档 |
| 旋转 / 平移 | 程序倾转 / 实际平移碰撞；无精确旋转扫掠 |

仍无通用应力求解、任意方向布尔切割、动态物体抓钩、敌人生命系统或受砸扣血。交汇处的风险来自大块遮挡、撞停和失去运动路线。普通塔可以有悬空残墙；地面与地基不可破坏。
