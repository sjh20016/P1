# 0.06 持续运行与性能

## 结论

36 栋开放区已经能维持五分钟连续飞行、破坏与回访，损伤状态和活动对象数量没有出现失控增长。当前证据支持保留这一级规模；不支持直接推广成数百栋同精度建筑，也不构成“稳定 60 FPS”的验收。

## 最终五分钟诊断运行

Intel UHD Graphics 730 / OpenGL 3.3 Compatibility / 驱动 32.0.101.7088 / Godot 4.7.2，窗口 1280 × 800。使用 `--audio-driver Dummy` 隔离先前的音频设备异常；发布版仍使用正常音频。测试关闭刻意的 hit stop，保留场景、HUD、粒子、碎块、碰撞与连锁。

| 指标 | 实测 |
|---|---:|
| 真实时长 / 帧数 | 300.008 秒 / 17,731 |
| 平均 FPS | 59.10 |
| 1% 低帧 FPS | 44.57 |
| 帧时间 p50 / p95 / p99 | 16.88 / 18.22 / 19.06 ms |
| 最大单帧 | 166.40 ms |
| 超过 33.33 / 50 ms 的帧 | 8 / 3 |
| 访问 / 回访次数 | 226 / 190 |
| 实际受损建筑 / 回访状态错误 | 36 / 0 |
| 结构断裂 / 二次连锁 / 稳定废墟 | 3 / 3 / 3 |
| 结束时活动宏块 / 排队宏块 | 0 / 0 |
| 采样峰值碰撞代理 / 节点 | 501 / 1,480 |
| 采样峰值 Godot 静态内存 | 75.90 MB |
| 结束时 Godot 静态内存 | 74.52 MB |
| 单次碰撞激活最长 / 单塔初建最长 | 1.888 / 0.504 ms |

1% 低帧 = 1000 ÷ 最慢 1% 帧的平均毫秒数。节点、内存、碰撞数等约每个物理秒采样一次，可能漏掉瞬时峰值；静态内存不是整进程内存或显存。前 60 次采样内存约 69.42–72.73 MB，最后 60 次约 73.37–75.60 MB；新增损伤和废墟有有限成本，本次没有证明无限时长无增长。

最大两次停顿出现在第 13.62 与 14.09 秒、首次结构连锁附近。尚未通过逐帧 CPU/GPU 分析确定原因，不能把它们归因于某个单一系统。后续应优先定位这些首用尖峰，而不是加大地图。

自动路线以约 65 m/s 连续移动测试角色，并从正式伤害入口命中建筑。它不是人工驾驶，也不证明抓取路线有趣；真实角色扫掠穿墙和抓点行为由单独功能测试验证。

## 保留的失败证据

第一次采用默认音频的五分钟运行完成 224 次访问、188 次回访，状态错误为 0，但出现 `WASAPI: GetBufferSize error` / 输出设备失效与秒级停顿。该次帧采样合计仅约 282 秒，因此不采用其均值作为完整 300 秒表现；最终诊断已修正计时位置，覆盖完整运行间隔。设备错误与停顿同时出现，不足以证明所有停顿都由音频引起。

更早的旧城预加载导致图形启动发生内存分配失败。新入口改为按需加载旧 358 塔后，短测、截图及两次五分钟开放区运行均能启动。F12 旧塔林自身的高展开成本仍存在。

诊断运行的原始 JSON 中 `workload.audio` 被旧检测代码误记为 `default`：引擎参数已被消费，脚本不能据此识别驱动。实际启动命令明确指定 Dummy；原始记录保持原样，脚本现已移除这个错误推断。
