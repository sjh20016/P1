# 0.03 试玩与验证记录

2026-09-10。Windows，Godot 4.7.2.stable.official.ed1daf0bf，UHD 730，OpenGL Compatibility，1280×800，默认 120 Hz 物理。

## 实际做过的试玩

动作由脚本驱动真实游戏节点、输入动作、碰撞与渲染，截图由游戏视口直接输出。第一段从正常出生点开始，没有中途传送；后半段逐站放置玩家验证。没有声称完成一次真人无辅助通关，也没有声称脚本能判断“爽”。

| 实景片段 | 观察 |
|---|---|
| 出生 → 上方环 → 改抓 Gate A → 撞穿 | 两次实际 shoot 均成功，达到 30 m/s 约需首钩后 0.375 秒；撞前约 69.55、处理后约 57.61 m/s，后续截图约 53 m/s，进入第三站 |
| 右上环 → 下掠横梁 | 实际射线选中 AnchorSweep；Gate B 断开，檐板反应启动，截图时约 68.66 m/s；不需要用身体撞中横梁 |
| 撞开入口 | ShellFront 破坏，角色穿入房间前部；隔离测试另验证入口后锚点从遮挡变为可抓 |
| 危险下坠 → 抓回上方环 | 从 y=-121、向下 24 m/s 抓 AnchorRescue，约 1.5 秒物理演进后向上约 29.26 m/s；记录 1 次 recovery，没有 reset |
| 重型终点 | 55 m/s 初速冲入，终点门破坏，继续以约 38.60 m/s 飞出，完成界面与自动保存触发 |

后四项使用 `scripted_station_setup` 事件标记，完成界面显示 STATION CHECK COMPLETE。用于验证站点功能的 3 秒左右遥测片段不是整条路线的通关时间。“三分钟路线”是预期试玩与重试尺度，尚待真人测得完成时间分布。

## 各实验的体验观察与问题

| 实验 | 最有潜力的片段 | 最迟钝 / 失速处 | Miss、卡住、Reset 与下一步 |
|---|---|---|---|
| M01 纯弹簧 | 拉力逐渐建立后释放，重力继续增加速度 | 达到 30 m/s 约 0.79 秒，缺少命中瞬间的位移变化 | 不选为默认；松钩不掉速，但精确绕角、连续钩的舒适度仍要真人比较 |
| M02 径向摆锤 | 挂绳后的径向速度受约束、切向运动继续 | 达到 30 m/s 约 1.22 秒；静止 / 低速起步最弱 | 去掉远离锚点的径向分量可能让错误角度更难挽回；保留作实验，不扩展技能补偿它 |
| M03 Hybrid | 抓环 → 立即拉出 → 改抓墙 → 撞穿后继续飞；一次释放保留约 99.2% 短时速度 | 接近锚点约 3 m 内 motor 衰减；持续按着容易撞锚，主动松钩更顺 | 两手脉冲共用冷却，速度限制 82。高速度下下一目标的选择仍是主要学习点；需要真人检验是否过度强拉 |
| Target Assist | 固定偏角夹具由中心 3/9 命中提高到窄锥 9/9 | 中心无目标时才做额外查询；不存在目标时仍应明确 Miss | 细柱位于离散采样间隙、超出 150 m、相机看见但身体视线被挡时仍会 Miss。密集墙面下前景表面可成为候选，需观察是否符合意图 |
| Body / Slash | 正撞有速度损失仍能通过；绷绳扫切保持高速并打开下一抓取角度 | 重门削弱法向速度至 68%；低于破坏法向阈值时仍会正常撞墙停下 | 身体与切割反馈当下可见；音效重量和 Hit Stop 强弱未做真人盲测。近距离大碎片短暂遮挡画面仍可优化 |
| Fall / Wall | 危险下坠抓回上方、由负垂速变正；Shift 短停后 Space 蹬出 | 持钩向较低目标猛冲可能继续下坠；主动贴墙是节奏停顿，保持可选 | 旧高度线不再 reset；真正无表面且不再上升才复位。远离塔林可能长时间找不到抓点。所有附近锚点被破坏后可用 R；不保证任何错误都能救回 |

当前最值得真人反复试的组合是：**抓上方环拉出 → 早点释放 → 斜着撞开墙 → 顺着新缺口改抓另一面**；其次是抓住右上环并向横梁侧下方掠过。此处是基于运动连续性与可见结果选择的候选，不是 AI 主观“最爽”评分。

当前最大遗留问题：高速下转头选择下一抓点的认知负担、低速贴近锚点时的顿挫、少数门槛以下的撞墙失速，以及极端全分段状态的帧率。接下来优先用真人 F8 记录定位失败段，不追加新攻击。

## 自动遥测

`course_first_leg.json` 是真实出生点第一段；`course_stations_playtest.json` 是显式分站重放。报告 shots 与 successful_grapples 时注意：前者来自 shoot，后者还包括测试脚本直接 attach_to，因此不能把独立测试中的二者差异当成错误。

时间来自参与运行的物理 delta，Hit Stop 会影响它；界面课程钟来自课程 process delta。两者都不是显示器输入延迟测量。测试中禁用玩家控制或放置到新站点会影响时间与平均速度，所以跨片段比较必须看事件序列。

F8 保存字段包括首抓时间、发射 / Miss、抓取次数和距离、达速时间、均速、峰值、高速持续时间、释放速度、救援 / 重置、身体撞击 / 切割次数、撞前速度与损失。事件上限 5000、释放记录上限 2000，长时间运行保持有界。

## 工程验证

`tools/run_checks.ps1 -Rnd -Stress` 全部通过：8 组原有回归、4 组 0.03 专项，以及 21,600 次物理帧长期循环。长期测试主动交替双钩、松钩、复位并触发破坏，属于稳定性压力测试，主动复位次数不能解释为玩家自然失误次数。

- 长期峰值速度 55.903 m/s；活跃碎片峰值 40 / 48；墨迹峰值 241 / 768；243 次破坏事件。
- NaN、非法位置或超速帧数 0；最终碎片全部回收。
- 358 栋与 4,944 段的加载 / 破坏 / 保留邻段通过；8 组原有测试无回归。
- 切梁在 60、90、120 Hz 均成功；真实墙接触、Shift 短停、Space 蹬出、Q 蓄力、自动脱钩、双手共享冷却与连续重开课程均通过。
- 三次主场景载入 / 释放无资源泄漏。研发中出现过 DestructionManager 与 DestructibleSegment 的循环类型引用，已移除函数参数的循环强类型依赖并重测。

性能的全分段对照和范围限制见 `EXPERIMENTS_003.md`。原始证据保存在 evidence；本机完整日志在 build/rnd003 与 build/check-*.log。独立 Windows EXE 的最终结果见 `../VALIDATION.md`。

## 建议首次真人试玩

默认 3 号 Hybrid 完成或尝试路线约三分钟，按 F8；再按 1 或 2、F6 重新开始比较。优先反馈：哪一次明显想抓却没有抓住、哪次被拉得过猛、哪种撞击没感觉、何处突然失速或重置。可附 F8 JSON，保留失败现场比只报告“慢 / 不爽”更容易定位。
